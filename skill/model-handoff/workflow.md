# 可复用工作流与任务模板

> 使用model-handoff技能包审核【材料路径】，结果保存到【新目录】。先核对批准规则、数据资格与用途，再核对实际模型和输入合同。使用源端与目标端独立生成的结果做黄金比对，检查实际输入、类别、概率及拒绝行为。报告命令、文件哈希、环境、通过范围和待补项；不以回代或黄金一致性宣称独立测试性能。

1. 准入：引用已有文件身份审核结果，逐项记录参考标签、灰区/域外/隔离理由、批准规则版本及证据。只有实际批准才填写ELIGIBLE；未知填PENDING。训练标签与预测分开。
2. 用途：按来源谱系组织数据，保留训练/开发/工程回放/评估的真实历史用途。同源变体与连续帧不自动成为独立来源；谱系等权是本项目训练选择，新项目按自身目标决定。
3. 合同：冻结特征顺序、单位、dtype、版本、预处理归属、标签概率顺序、权重哈希及容差。LR内置缩放时不得重复标准化；百分数与比例显式换算。
4. 环境：只读记录Python、架构、依赖及实际模块路径。环境不兼容先保留错误，选择可验证的部署转换；转换不等于重训，需记录原权重和部署权重对应关系。
5. 黄金：源端保存实际输入/输出；目标端执行相同输入并保存结果；交付方独立复核。保留TRAIN黄金用途边界。失败不临时改容差。
6. 真实调用：消费已有有效输入，不新增Reader；保存帧身份、原Adapter状态、模型身份与输出。拒绝输入不补零、不沿用旧类别。把调用耗时、整轮耗时、端到端时延分开。
7. 收口：输出资格表、合同、文件身份、回放报告、真实调用审核及限制。已有证据复用，只有明确缺项才提出补测。

8. 成对评估：有实际授权和冻结参考标签后，分别保存各模型在同一输入上的结果，按references/paired-evaluation.md计分。保留缺失、拒绝和错误，原始数据不按模型输出筛选。选择用途需登记；工程候选不等于全面占优或正式发布。
